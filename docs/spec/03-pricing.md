# 가격 산정 규격

## 1. 병더리움(코인) 가격 산정

### 1.1 요구사항

| ID | 강도 | 요구사항 |
|---|---|---|
| SPEC-COIN-1 | 필수 | 코인 가격은 매수·매도와 무관하게 확률적으로만 변동한다. |
| SPEC-COIN-2 | 필수 | 일일 변동률 범위는 [-40%, +80%]다(이전 [-40%, +200%], 그 전 [-50%, +300%]. 초반 안정기 회차는 SPEC-COIN-6). |
| SPEC-COIN-3 | 필수 | 상승일 확률 ≈ 30%, 하락일 확률 ≈ 70%다. |
| SPEC-COIN-4 | 필수 | 상·하한 근처 극단값의 발생 빈도를 낮게 억제한다(분포 모양 제약). |
| SPEC-COIN-5 | 필수 | 10회 누적 결과의 중앙값이 원금 수준을 유지한다(로그 기대값 ≈ 0). |
| SPEC-COIN-6 | 필수 | 1회차부터 `coin_calm_rounds`회차(기본 3)까지는 일일 변동률 범위를 [-10%, +30%]로 좁힌다. 상승일 확률과 분포 모양(지수)은 평소와 같다(v0.4, [§1.5](#15-초반-안정기-v04)). |
| SPEC-COIN-7 | 필수 | 안정기 없이 10회 모두 평소 범위로 움직여도 누적 배수가 20배(표시 상한 5,000,000원)를 넘을 확률은 1% 미만이다(v0.4). 시뮬레이터(F-13)로 확인한다. |

### 1.2 알고리즘 (매 운영일 18:00, 1회)

```text
입력: 현재가 P, 회차 n, p_up=0.30, up_exp=2, down_exp=2, cap=+0.80, floor=-0.40,
      calm_rounds=3, calm_cap=+0.30, calm_floor=-0.10

0. if n <= calm_rounds:           # 초반 안정기 (SPEC-COIN-6)
       cap, floor = calm_cap, calm_floor
1. p ~ Uniform(0, 1)
2. X ~ Uniform(0, 1)
3. if p < p_up:                  # 상승일 (약 30%)
       r = cap   * X^up_exp      #  = +80% * X^2  (안정기 +30% * X^2)
   else:                         # 하락일 (약 70%)
       r = floor * X^down_exp    #  = -40%  * X^2  (안정기 -10% * X^2)
4. P' = round( P * (1 + r), 10원 )

출력: 새 가격 P'
```

균등난수 두 개(p, X)만 사용하므로 별도 정규분포 라이브러리가 필요하지 않다.

### 1.3 검증 기준 (파라미터 확정 시 필수 충족)

- 상승일 비율 ≈ 30%, 하락일 비율 ≈ 70%.
- 하락일 평균 ≈ -13.3%, 상승일 평균 ≈ +26.7%.
- 로그 기대값 E[ln(1+r)] ≈ 0 (기본 파라미터에서는 ≈ -0.042로 SPEC-COIN-5를 충족하지 못한다. 아래 검토 필요 참조).
- 안정기 없이 10회 누적 20배 초과 확률 < 1% (SPEC-COIN-7).
- 10회 경로 시뮬레이션 ≥ 1,000회로 분포·순위 분산 확인(F-13).

참고 — 산술 기대값은 하루 약 -1.3%로 음수다(이전 기본값 [-40%, +200%]·X³에서는 +5.7%였다). 상승일 평균(+26.7%)이 하락일 평균(-13.3%)의 두 배에 그쳐, 상승일 30%·하락일 70%에서는 상쇄되지 않는다.

> **검토 필요 (2026-10-04)** — 기본값을 상승폭 지수 2, 상한 +80%로 바꾸면서 로그 기대값이 평소 회차 기준 약 -0.042가 되어 SPEC-COIN-5(중앙값이 원금 수준 유지)를 충족하지 못한다. 10회 누적 중앙값은 안정기 포함 약 0.74배, 없이 약 0.65배다. 20배 초과 확률은 사실상 0이므로 SPEC-COIN-7은 충족한다. 중앙값을 0.88배 근처로 되돌리려면 상승 확률이나 상한을 올려야 한다(예: 상한 +200%·X³가 v0.4 값). 이 기본값이 의도한 것인지 F-13에서 확인한다.

> **이전 검토 필요 (v0.2)** — 일일 통계(상승일 30.0%, 하락일 평균 -16.7%, 상승일 평균 +74.9%, E[ln(1+r)] ≈ -0.003, 일일 분위수)는 원문과 일치한다. 그러나 누적 배수는 원문 기재값과 다르다. 중앙값은 1.0배가 아니라 약 0.88배이고, 상위 1% 경로는 20배를 넘는다. 코인 가격은 전 참가자가 공유하는 단일 경로이므로, 이벤트 전체가 5,000,000원(20배) 표시 상한에 걸릴 확률이 약 2%다. SPEC-COIN-5 충족 여부와 누적 상한 정책은 파라미터 확정(F-13) 시 다시 판단한다. v0.4에서 평소 범위를 [-40%, +200%]로 줄여 20배 초과 확률을 안정기 없이도 약 0.45%(1% 미만, SPEC-COIN-7)로 낮췄고, 초반 안정기(3회)를 포함하면 약 0.15%다. 중앙값(약 0.88배)은 그대로다.

**누적 상한** — 별도 누적 상한은 두지 않는다. 일일 상한이 +80%라 누적도 좁게 닫혀 있다(10회 기준 20배 초과 확률 0.00%, 위 검토 필요 참조). 표시 한계가 필요하면 [고정 상수](02-parameters.md#1-고정-상수)의 5,000,000원을 안전 상한으로 둔다(권장).

> **설계 근거** — 상승 30% / 하락 70%는 그 자체로 강한 하락 압력이다. 코인이 보유 가치가 있으려면 드문 상승일의 상승폭이 잦은 하락일의 하락폭보다 훨씬 커야 하므로(하락일 평균 -13% ↔ 상승일 평균 +50%), 상한은 하한과 함께 정해 로그 기대값이 0 근처가 되게 한다. v0.3까지는 [-50%, +300%]였으나, 10회 누적 20배 초과 확률(약 2%)을 1% 미만으로 낮추려고 v0.4에서 상·하한을 [-40%, +200%]로 함께 줄였다(로그 기대값 약 -0.003 → -0.004, 누적 중앙값 약 0.88배 그대로). 상한 근처 값이 자주 나오면 이벤트가 운 한 번으로 결정되므로, 상승폭은 X³, 하락폭은 X²로 낮은 쪽에 몰리게 잡아 범위는 유지하되 극단 빈도만 눌렀다. 변동이 10회뿐이라 기대값을 0%로 고정하면 우측 꼬리가 거의 등장하지 않아 코인이 '보유할수록 손실인 벌칙 자산'이 된다. 따라서 산술 기대값이 아니라 로그 기대값(누적 중앙값)을 0으로 맞춘다.

### 1.5 초반 안정기 (v0.4)

1회차부터 `coin_calm_rounds`회차(기본 3회차)까지는 상·하한만 `coin_calm_cap`(+30%)·`coin_calm_floor`(-10%)로 바꿔 추출한다. 기본 일정에서는 10/6·10/7·10/8 정산, 즉 10/7~10/9 시작가가 안정기다. 4회차(10/9 정산, 10/10 시작가)부터는 평소 범위 [-40%, +80%]로 돌아간다. 상승일 확률(30%)과 지수(X²·X²)는 그대로다.

| 항목 | 안정기 (-10% ~ +30%) | 평소 (-40% ~ +80%) |
|---|---|---|
| 상승일 비율 | 30% | 30% |
| 상승일 평균 | 약 +10.0% | 약 +26.7% |
| 하락일 평균 | 약 -3.3% | 약 -13.3% |
| 산술 평균 | 약 +0.7% | 약 -1.3% |
| 로그 기대값 E[ln(1+r)] | 약 +0.004 | 약 -0.042 |
| 하위 5% / 중앙값 / 상위 5% | 약 -8.6% / -0.8% / +20.9% | 약 -34.5% / -3.3% / +55.6% |
| 상위 1% | 약 +28.0% | 약 +74.8% |

안정기 3회를 모두 최대로 움직여도 누적 -27%(0.9³) ~ +120%(1.3³) 안이다. 값은 기본 파라미터로 경로 1,000,000회 몬테카를로(F-13) 결과이며, 관리자 시뮬레이터는 평소 회차와 안정기 회차의 일일 통계를 따로 보여 준다.

> **설계 근거 (v0.4)** — 첫날 코인을 산 참가자가 1회차 대형 상승(이전 +200%, 현행 최대 +80%) 한 번으로 크게 앞서거나 급락으로 일찍 탈락하면, 참가자가 규칙에 익숙해지고 중도 참가자가 합류하기 전에 순위가 굳는다. 그래서 초반 며칠(3~4일)은 변동폭을 좁힌다. 상·하한을 같은 비율로 줄이면(예: 둘 다 1/10) 양수인 산술 기대값은 비례해 줄지만 변동성 손실은 제곱으로 줄어 로그 기대값이 양수가 되고, 안정기 동안 코인이 오르는 쪽으로 기운다. 상한 +30%·하한 -10%는 로그 기대값을 평소와 비슷한 0 근처(약 -0.003)에 맞춘 값이라, 누적 중앙값은 거의 그대로 두고 양쪽 꼬리만 좁힌다. 안정기 길이는 `coin_calm_rounds`로 조정한다(4로 올리면 10/10 시작가까지).

## 2. 주식 가격 산정

### 2.1 요구사항

| ID | 강도 | 요구사항 |
|---|---|---|
| SPEC-STOCK-1 | 필수 | 주식 가격은 당일 참가자 전체의 총매수 쏠림에 역방향으로 반응한다. 쏠림이 주된 동인이며, 무작위 요소는 [§2.5](#25-매수지분-잡음)의 작은 잡음뿐이다. |
| SPEC-STOCK-2 | 필수 | 일일 변동률 범위는 [-30%, +30%]다. |
| SPEC-STOCK-3 | 필수 | 최저가 하한 1,000원을 적용한다. |
| SPEC-STOCK-4 | 필수 | 매수지분에 작은 Gumbel 잡음 배수를 곱한다(`stock_noise_scale`, 기본 0.1). 0이면 잡음 없이 당일 매수만으로 결정된다. 잡음 배수는 정산 로그에 남긴다([§2.5](#25-매수지분-잡음)). |
| SPEC-STOCK-5 | 필수 | 다음 운영일의 호재·악재는 정산에서 쏠림 변동률(클램프 뒤)에 곱으로 얹는다. ±30%는 쏠림 변동률에만 적용되므로 적용률은 ±30%를 넘을 수 있다([§3](#3-호재악재)). |

### 2.2 정의 및 공식

```text
Bᵢ      : 종목 i 당일 매수금액
Bᵢ′     = Bᵢ + L                      # 가상 유동성 L 적용. 예시는 L=0 가정.
Bᵢ″     = Bᵢ′ × exp( τ·(Gᵢ − γ) )     # 매수지분 잡음(§2.5). Gᵢ ~ Gumbel(0,1), γ ≈ 0.5772. 예시는 τ=0 가정.
B_total = Σ Bᵢ″  (i = 1..4)
기준선   = B_total / 4
rᵢ      = Bᵢ″ / (B_total/4) = 4·Bᵢ″ / B_total    # rᵢ ∈ [0, 4], rᵢ=1이 기준선

변동률ᵢ = clamp( 30% × (1 − rᵢ), −30%, +30% )           # 쏠림 변동률
적용률ᵢ = (1 + 변동률ᵢ) × (1 + 뉴스ᵢ) − 1                 # 뉴스ᵢ: 다음 운영일 호재 +x / 악재 −x, 없으면 0 (§3)
새 가격  = max( 1000, round( 현재가 × (1 + 적용률ᵢ), 10원 ) )
```

기준선보다 적게 매수된 만큼 오르고 많이 매수된 만큼 내린다. rᵢ = 0(아무도 매수 안 함)에서 +30%, rᵢ = 2(기준선의 2배)에서 -30%로 상·하한에 도달한다. τ = 0이면 Bᵢ″ = Bᵢ′라 아래 예시와 같이 당일 매수만으로 결정된다.

### 2.3 예외 처리 (필수)

- **B_total = 0** (전 종목 매수 0, L = 0): 전 종목 변동률 0%. 잡음 배수는 양수라 이 판정에 영향이 없다. L > 0이면 이 상황은 발생하지 않으므로 L 적용 권장.
- **특정 종목만 Bᵢ′ = 0**: rᵢ = 0 → 자동으로 +30% 적용.
- **하한**: 산출 가격이 1,000원 미만이면 1,000원으로 고정.
- **반올림**: 모든 가격은 10원 단위.

### 2.4 계산 예시 (L=0, 총매수 4,000만원 → 기준선 1,000만원)

| 종목 | 당일 매수금액 | 쏠림 지수 r | 변동률 | 반영 후 가격 |
|---|---|---|---|---|
| 삼수전자 | 2,000만원 | 2.0 | -30% | 75,000 → 52,500원 |
| SK로우닉스 | 1,200만원 | 1.2 | -6% | 170,000 → 159,800원 |
| 미래대 | 600만원 | 0.6 | +12% | 40,000 → 44,800원 |
| LB | 200만원 | 0.2 | +24% | 14,000 → 17,360원 |

> **설계 근거** — 인기 종목에 몰리면 손해가 되므로 참가자는 비인기 종목을 찾게 되고 매수가 4종목에 분산된다. 변동이 10회뿐이라 rᵢ=2에서 이미 하한에 닿도록 하락 감도를 높였고, 실제 쏠림 범위(대략 rᵢ=0.5~1.8)에서 하루 ±15~25% 변동이 나온다. 감도 조절이 필요하면 계수 30%만 파라미터로 노출한다.

### 2.5 매수지분 잡음

정산 때 종목마다 표준 Gumbel 난수 Gᵢ = −ln(−ln Uᵢ)(Uᵢ ~ U(0, 1))를 하나씩 뽑아, 가상 유동성을 더한 매수금액에 배수 exp(τ·(Gᵢ − γ))를 곱한 Bᵢ″로 쏠림 지수를 계산한다. γ ≈ 0.5772는 Gumbel의 평균이라 ln 배수의 평균은 0이고, 표준편차는 τ·π/√6 ≈ 1.28τ다. 로그 매수지분에 Gumbel 잡음을 더하는 것과 같으므로(Gumbel-max), 쏠린 종목이 매수금액에 비례해 확률적으로 "쏠린 것"으로 판정된다. 전 종목에 같은 배수가 걸리면 지분이 그대로이므로 잡음은 종목 사이의 상대 지분만 흔들고, 클램프 전 변동률의 합은 잡음과 무관하게 0이다(시장 전체가 한쪽으로 쏠리지 않는다).

| 상황 | τ = 0 (잡음 없음) | τ = 0.1 (기본) | τ = 0.2 |
|---|---|---|---|
| 아무도 안 삼 (전 종목 L만) | 전 종목 0% | 종목당 -6% ~ +5% (5~95%), σ ≈ 3.5%p | -13% ~ +9%, σ ≈ 7%p |
| 20명 규모 (L=500만, 매수 합 800만) | -8.6% ~ +6.9% | 결정론 부호가 뒤집히는 정산 약 40% | 약 63% |
| 규격 예시 §2.4 (L=0) | -30% ~ +24% | 부호 뒤집힘 약 5% | 약 24% |

(경로 50,000회 몬테카를로, 2026-10-04.) τ는 `stock_noise_scale`로 조정하며 0이면 v0.4까지의 결정론 산정과 같다. 2 이하만 허용한다. 뽑은 배수는 정산 로그 `stocks[].noise_factor`에 남긴다(τ = 0이면 `null`).

> **설계 근거 (2026-10-04)** — 테스트 서버에서 주문이 없는 날 주식 4종목이 모두 0.00%로 멈추고, 주문이 있어도 L이 신호를 눌러 변동이 거의 없다는 문제가 나왔다. 변동률 자체에 독립 잡음을 더하면 네 종목이 한꺼번에 오르내릴 수 있고 쏠림 공식과도 따로 논다. 매수지분에 곱하는 방식은 공식과 클램프, "쏠림에 역방향" 성질을 그대로 두고, 매수금액이 큰 종목일수록 잡음으로 더 쏠린 것으로 판정될 확률이 높다. τ는 쏠림 신호를 덮지 않도록 작게(0.1) 둔다. 20명 규모에서 τ=0.1만 돼도 비인기 종목 매수의 유인이 열 번 중 네 번쯤 뒤집히므로, 변동이 더 필요하면 τ를 올리기보다 L을 낮추는 쪽이 설계를 유지한다.

## 3. 호재·악재

### 3.1 요구사항

| ID | 강도 | 요구사항 |
|---|---|---|
| SPEC-NEWS-1 | 필수 | 운영일 D의 뉴스는 전날 18:00 정산에서 해당 주식의 쏠림 변동률에 곱으로 얹혀(호재 ×(1 + x), 악재 ×(1 − x)) D 시작가에 반영되고, D 09:00 공시와 함께 발표된다. 참가자가 뉴스를 보는 시점에는 이미 가격에 들어가 있다. |
| SPEC-NEWS-2 | 필수 | 뉴스는 주식 4종목에만 적용한다. 병더리움은 대상이 아니다. |
| SPEC-NEWS-3 | 필수 | 운영일·종목당 뉴스는 1건이다. 무작위 뉴스는 전날 18:00 정산에서(코인·주식 잡음 난수 다음, 주식 가격 산정 전) 다음 운영일 몫으로 확률 `news_probability`(기본 0.5)로 1건 이하 생성한다. 호재·악재는 반반, 종목은 균등, 크기 x는 `news_rate_min`~`news_rate_max`(기본 10%~20%)에서 1% 단위 균등이다. |
| SPEC-NEWS-4 | 필수 | 관리자는 시작가가 아직 정해지지 않은 운영일(전날 정산 전, 첫 운영일·마지막 운영일 제외)에 뉴스를 직접 쓰거나 지울 수 있다. 같은 날·종목에 이미 있으면(무작위 생성분 포함) 덮어쓴다. 그날 뉴스가 이미 있으면 무작위 뉴스는 만들지 않는다. |
| SPEC-NEWS-5 | 필수 | 아직 공시되지 않은 운영일의 뉴스는 참가자에게 보이지 않는다(정산으로 가격이 정해졌어도 09:00 공시 전까지는 비공개). 적용된 뉴스 효과는 그 정산의 로그에 남긴다. |

### 3.2 알고리즘 (전날 18:00 정산 안, 코인·주식 잡음 난수 다음, 주식 가격 산정 전)

```text
입력: 다음 운영일 D(반영일이 있어야 함), p_news=0.50, x_min=0.10, x_max=0.20

0. D에 뉴스가 이미 있으면(관리자 작성) 끝.
1. u ~ U(0,1); u ≥ p_news 이면 끝(뉴스 없음).
2. 종목 = 주식 4종목 중 균등 추출
3. 종류 = 호재 (확률 1/2) / 악재
4. x = round( x_min + (x_max − x_min)·U(0,1), 0.01 )   # 하한·상한이 엇갈려 있으면 정렬해 쓴다
5. 기사 = 종목별 기사 풀(호재 5·악재 5) + 공통 예비 풀(호재 3·악재 3, 종목명 치환) 중 이번 이벤트에서
   아직 쓰지 않은 것에서 균등 추출(다 썼으면 전체에서). 제목·부제·본문·바이라인이 함께 정해진다(§3.3).

같은 정산 → 적용률 = (1 + 쏠림 변동률)(1 ± x) − 1 → D 시작가 확정.  D 09:00 공시 → 가격과 뉴스 함께 공개.
```

이벤트 첫날은 앞선 정산이 없으므로 뉴스가 없다(관리자도 쓸 수 없다). 마지막 운영일은 반영일이 없어 뉴스를 만들지도 받지도 않는다.

### 3.3 기사 풀

무작위 뉴스는 제목 한 줄이 아니라 기사다. 종목마다 캐릭터에 맞춘 패러디 기사(삼수전자: 세 번째에 성공하는 끈기, SK로우닉스: 이름은 low인데 주가는 최고가, 미래대: 금융사인지 대학인지 모호, LB "Life is Bad": 만년 저평가와 자조 유머)를 호재 5건·악재 5건씩 두고, 어느 종목에나 쓰는 공통 예비 기사를 호재 3건·악재 3건 둔다. 기사는 제목(120자)·부제(120자)·본문 2~3문장(600자)·바이라인(가상 매체 병더리움경제TV·명륜뉴스·율전일보)으로 이루어진다. 원문은 `backend/src/study_invest/news_pool.py`에 있다.

제약: 실존 기업·인물을 거론하지 않는다(패러디 이름만). 본문에 변동률 숫자를 쓰지 않는다(크기는 §3.2에서 따로 뽑아 배지로 보인다). 호재는 명확히 긍정, 악재는 명확히 부정이다. 같은 종목에서는 이번 이벤트에 이미 나온 제목을 피한다. 관리자가 쓰는 뉴스는 부제·본문·바이라인이 선택이며, 비우면 참가자에게 제목만 보인다.

> **설계 근거 (2026-10-04)** — 주식은 참가자 전체의 쏠림에만 반응하므로 "읽고 판단할 거리"가 없다는 피드백에서 나왔다. 처음에는 아침에 발표하고 저녁 정산에 반영했으나, 악재를 보고 모두 매도하는 단순 대응이 정답이 되어 재미가 없다는 피드백으로 **발표 시점에 이미 가격에 반영**하도록 바꿨다. 뉴스는 예측 재료가 아니라 그날 가격이 왜 움직였는지 설명하는 이야기이고, 참가자의 판단은 여전히 쏠림 쪽에 있다. 효과를 쏠림 변동률에 더하지 않고 곱하는 이유는 ±30% 클램프와 독립적으로 동작시키기 위해서다. 더하면 클램프에 걸린 종목에서 뉴스가 사라진다. 코인은 분포가 따로 조정돼 있어 대상에서 뺐다.
