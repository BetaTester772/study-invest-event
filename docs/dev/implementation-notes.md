# 구현 노트 — 규격 해석 및 가정

규격서(v0.3)가 명시하지 않았거나 해석이 필요했던 부분을 구현이 어떻게 처리하는지 기록한다. 기획 확인 후 달라지면 코드와 이 문서를 함께 고친다.

## 구조

| 영역 | 위치 | 비고 |
|---|---|---|
| 도메인(순수 함수) | `backend/src/study_invest/{money,params,instruments,event_calendar,pricing,simulator}.py` | DB·프레임워크 의존 없음 |
| 영속·서비스 | `models.py`, `services/*.py` | SQLAlchemy 2.0, PostgreSQL(운영)·SQLite(테스트 기본) |
| HTTP API | `api/*.py` | FastAPI. 계약은 [api.md](api.md) |
| 배치 | `services/market.py` `run_due`, `cli.py` | 앱 내 스케줄러(`STUDY_INVEST_SCHEDULER=1`) 또는 cron + `study-invest run-due` |
| 마이그레이션 | `backend/migrations` | Alembic. 컨테이너 시작 시 `alembic upgrade head` |
| 프론트엔드 | `frontend/` | React + Vite. 공용 컴포넌트(`src/components/ui`) 먼저, 페이지는 조합 |

## 비동기 원칙 (서비스 전체가 멈추지 않게)

`async def` 라우트·의존성은 이벤트 루프 스레드에서 직접 실행된다. 그 안에서 동기 I/O(DB·파일)를 하면 끝날 때까지 **모든 요청이 멈춘다.** 동기 `def`는 FastAPI가 스레드풀에서 실행하므로 여러 요청이 동시에 처리된다.

| 구분 | 방식 | 해당 |
|---|---|---|
| DB·파일을 쓰는 라우트·의존성 | 동기 `def` → 스레드풀 | 거의 모든 라우트, `get_session`, `optional_participant`, `current_params`, 인증 업로드, 이미지 응답 |
| I/O 없는 의존성·라우트 | `async def` → 이벤트 루프에서 즉시 | `get_state`, `get_now`, `bearer_token`, `current_participant`, `require_admin`, `/api/health`, 예외 핸들러 |
| CPU 바운드(수 초) | `async def` + 프로세스 풀 `await` | `/api/admin/simulate` (스레드에서 돌리면 GIL 때문에 다른 요청도 느려짐) |
| 배치 스케줄러 | asyncio 태스크 + `asyncio.to_thread` | `_scheduler` → `run_due` |

- **회귀 방지**: `install_event_loop_guard`가 이벤트 루프 스레드에서 실행되는 SQL을 감지한다. 테스트는 `raise`(해당 테스트 실패), 운영 기본값은 `warn`(로그). `tests/test_async_policy.py`는 async 라우트·의존성 허용 목록을 고정하고, 업로드가 스레드풀에서 돌며 시뮬레이션 중에도 `/api/health`가 응답하는지 확인한다.
- **풀 크기**: 스레드풀 40(`STUDY_INVEST_THREADPOOL_SIZE`), api 연결 풀 20(대기 10초 넘으면 503), 배치 전용 풀 2. 풀 설계와 연결 예산은 [db-pools.md](db-pools.md).
- **워커 수**: 앱 내 스케줄러는 프로세스마다 돈다. `uvicorn --workers N`이나 레플리카를 늘리면 스케줄러는 한 곳에서만 켜고(`STUDY_INVEST_SCHEDULER=1`), 나머지는 끈다. 여러 개가 동시에 돌아도 DB 제약으로 중복 공시·정산·지급은 막히지만 오류 로그가 남는다.

## 동시성 (PostgreSQL 기준)

| 상황 | 처리 |
|---|---|
| 같은 참가자의 현금·보유 변경(주문·보상) | 모두 `lock_participant`를 거친다: 참가자 행과 보유 행을 `FOR UPDATE`로 잠그고 **다시 읽는다**(세션에 있던 옛 값도 덮어씀). 요청 초반에 읽은 현금·보유는 쓰지 않는다. |
| 18:00 경계의 주문 vs 정산 | 주문은 운영일 행에 `FOR SHARE`, 정산은 `FOR UPDATE`. 정산은 진행 중인 주문이 끝난 뒤 집계하고, 정산 이후 주문은 `MARKET_CLOSED`. |
| 배치 중복(워커·레플리카·수동 실행) | 공시·정산·수동 가격은 `pg_advisory_xact_lock`으로 직렬화. 스케줄러는 `try` 잠금이라 다른 곳이 실행 중이면 조용히 건너뛴다. |
| 동시 중복 인증·등록 | 세이브포인트로 유니크 제약 위반을 잡아 409(`ALREADY_CERTIFIED`·`IDENTITY_TAKEN`·`NICKNAME_TAKEN`). 그 밖의 무결성 충돌도 전역 핸들러가 409 `CONFLICT`. |
| 전일 정산이 계속 실패 | 09:00 공시는 그대로 진행해 전일 가격을 이월한다(오늘 장은 열림). 이월 뒤에는 전일 정산을 다시 돌리지 않는다. |
| 큰 요청 본문 | ASGI 미들웨어가 `Content-Length`로 먼저 거부하고, 길이 없는 스트림은 받는 도중 한도 초과 시 413. 업로드 경로는 사진 한도 + 64KiB, 나머지는 1MiB. |
| 스케줄러 지연 | 30초 주기와 별개로 09:00·18:00 정각 직후 깨어난다. |

SQLite(테스트 기본)는 행 잠금이 없으므로 동시성 테스트(`tests/test_concurrency.py`)는 PostgreSQL에서만 돈다.

## 수치 한계

모든 가격·수량·금액이 DB의 BIGINT와 정수 연산 범위 안에 머물도록 한 곳(`params.py`)에서 정한다.

| 한계 | 값 | 적용 |
|---|---|---|
| `PRICE_MAX` | 10억 원 | 가격 산정 결과(코인·주식 모두 클램프), 수동 개입가, 가격 파라미터 |
| `QUANTITY_MAX` | 10억 | 주문 수량 |
| `REWARD_QUANTITY_MAX` | 1,000 | 인증 1건당 보상 수량 |
| `AMOUNT_MAX` | 10^15원 | 가상 유동성 등 금액 파라미터 |
| `COIN_CAP_MAX` | 10.0(+1000%) | 코인 일일 상승 상한 파라미터 |

한 주문 금액은 최대 `PRICE_MAX × QUANTITY_MAX = 10^18`로 BIGINT(약 9.2×10^18) 안이다. 실수 파라미터는 NaN·Infinity를 거부한다.

## 해석·가정

### 장 운영·체결

- **주문 접수 시간**은 KST `[09:00, 18:00)`이다. 18:00:00 주문은 마감으로 거부한다.
- **시작가 공시 전 주문**(09:00 배치가 아직 안 돈 경우)은 `MARKET_NOT_OPENED`로 거부한다. 정산이 끝난 날의 주문은 `MARKET_CLOSED`.
- **거부된 주문도 기록**한다(F-09). 사유 코드와 한국어 메시지를 함께 돌려준다.
- **1일 1종목 매수 상한**은 코인을 포함한 5종목 모두에 적용한다. 당일 체결된 **매수 금액 누적**으로 판단하므로, 매도 후 재매수해도 한도가 늘지 않는다. 한도 = `floor(총자산 × 0.4)`이며, 장중 가격이 고정이고 수수료가 없으므로 총자산은 장중에 변하지 않는다.
- **평균단가**: 매수 시 매입금액을 더하고, 매도 시 평균단가를 유지하도록 매입금액을 비례 차감(원 단위 반올림)한다.
- **수량 범위**: API는 저장 가능한 값(64비트 정수)만 받는다(밖이면 422). 그 안에서 1~10억이 아닌 수량은 `INVALID_QUANTITY` 거부 주문으로 기록한다.

### 가격·정산

- **반올림**: 10원 단위 사사오입(0.5는 올림). 파이썬 `round()`(은행가 반올림)는 쓰지 않는다. 주식 계산은 유리수(`Fraction`)로 정확히 한다.
- **주식 기준선**은 주식 종목 수(4)로 나눈다. 매수 집계 `Bᵢ`는 **체결된 매수만**이다(매도 미포함).
- **코인 표시 상한 5,000,000원**은 가격 자체에 적용하는 클램프다(파라미터 `coin_price_cap`, `null`이면 해제). 코인 최저가는 규격에 없으나 0원 방지를 위해 10원을 보장한다.
- **정산 가능 조건**: 해당일이 공시됐고, 18:00 이후이며, 다음 운영일이 아직 공시되지 않았어야 한다. 마지막 운영일(10-16)은 반영일이 없어 정산하지 않는다(`NO_ROUND`).
- **배치 실패**: 정산은 한 트랜잭션이라 실패 시 아무것도 기록되지 않는다. 다음 날 09:00까지 재실행되지 않으면 공시 배치가 **전일 가격을 그대로 이월**(`source=carry_over`)한다. 이월 후에는 전일 정산을 다시 돌릴 수 없다(장중 가격 불변 보장).
- **가격 이력 공개 시점**: 정산(18:00)이 다음 날 가격을 확정해 기록하지만, 시세 API는 **공시(09:00)된 운영일만** 보여준다.
- **수동 가격 개입**(F-11): 아직 공시되지 않은 운영일에만 가능하며, 정산 결과보다 우선한다(정산이 덮어쓰지 않음). 10원 단위 양수만 허용.
- **전일 대비 기준**: 공시(09:00) 때 "그 전에 공시된 마지막 시작가"로 확정한다. 며칠 앞서 넣은 수동 개입가도 그사이 정산된 가격 기준으로 변동률이 계산된다.
- **가격 파라미터**: `stock_min_price`, `coin_price_cap`은 10원 단위만 허용한다(모든 가격이 10원 단위를 유지).
- **정산 난수**: 운영은 `random.SystemRandom`. 추출한 `p`, `X`를 정산 로그에 남긴다.

### 공부 인증·보상

- **마감 시각**은 해당 분(分)까지 포함한다. 마감 23:59이면 23:59:59 제출도 당일로 집계한다.
- **1인 1일 1회**는 상태와 무관하다. 반려된 날짜도 다시 제출할 수 없다. 화면은 `GET /api/me/certification-status`(제출 API와 같은 함수 `submission_status`)만 보고 업로드 가능 여부를 정한다.
- **이미지 해시 중복**(SHA-256)은 자동 반려하지 않고 `duplicate_of`로 표시해 검수자가 판단한다. 형식은 매직 바이트로 확인한다(JPEG·PNG·WEBP·HEIC, 10MB 이하).
- **이벤트 기간 밖 날짜**로 집계되는 제출(시작 전, 마지막 날 마감 이후)은 거부한다.
- **보상**: 승인분 중 미지급·대상일 < 공시일인 인증을 09:00 공시 때 한꺼번에 지급한다. 병더리움 `reward_coin_quantity`개를 매입금액 0원으로 편입한다(평가손익에 반영). 마지막 날 인증분은 지급일이 없다.
- **반려 반복 → 경고 → 실격**의 기준 횟수는 규격에 없어 **관리자가 수동으로** 상태를 바꾼다. 관리자 참가자 목록에 반려 횟수를 보여준다.
- **실격**: 주문·인증 제출 불가, 보상 미지급, 랭킹 제외.
- **개인정보**: `study-invest purge-images`가 이벤트 종료 후 업로드 디렉터리의 인증 사진 파일을 **전부** 지운다(DB에 없는 파일 포함, 해시는 감사용으로 보존). 종료 후 30일 안에 실행해야 한다.
- **사진 파일과 트랜잭션**: 사진은 트랜잭션에 묶어 저장한다(`track_new_file`). 커밋되지 않고 끝나면(롤백·예외·커밋 없이 종료) 파일도 지운다.

### 참가자·랭킹

- **1인 1계정**: 식별자(사내 계정·학번 등)를 NFKC·대소문자 무시·앞뒤 공백 제거로 정규화한 **뒤** 길이를 검사하고 중복을 막는다(`normalize.py`). 닉네임도 NFC·공백 제거 뒤 2~20자. 전화번호처럼 형식이 여러 가지인 식별자를 쓰면 정규화 규칙을 추가해야 한다.
- **401 처리(프론트엔드)**: 요청마다 보낸 토큰·관리자 키를 기억하고, 401은 그것이 아직 현재 값일 때만 세션 거절로 본다. 로그아웃→로그인 사이에 늦게 도착한 이전 세션의 401이 새 세션을 끝내지 않는다.
- **로그인**: 규격에 인증 방식이 없어 식별자 + 비밀번호(scrypt) + Bearer 토큰으로 구현했다. 사내 SSO가 있으면 교체한다.
- **닉네임**은 유일하다(랭킹 공개명).
- **참가 신청**은 이벤트 종료일까지 받는다(중도 참가 허용, 시드 동일).
- **랭킹**: 총자산 100%, 동점은 공동 순위(1, 2, 2, 4). 인증 연속일수는 오늘 승인분이 없으면 어제부터 센다.
- **관리자 인증**: `X-Admin-Key` 헤더(환경 변수 `STUDY_INVEST_ADMIN_KEY`). 비어 있으면 관리자 API가 모두 막힌다.
